## 1. Введение

[svg](https://github.com/Daniil-17102007/engineering#1-%D0%B2%D0%B2%D0%B5%D0%B4%D0%B5%D0%BD%D0%B8%D0%B5)

**Food Delivery App** — это платформа для онлайн-заказа еды, которая объединяет пользователей, рестораны и службу доставки.

Приложение позволяет:

- Просматривать каталог ресторанов и блюд.
- Открывать карточку товара с его описанием, стоимостью, изображением и доступностью.
- Фильтровать предложения по кухне, рейтингу, стоимости и времени доставки.
- Добавлять товары в корзину, изменять их количество и удалять ненужные позиции.
- Оформлять заказ с указанием адреса, способа получения и способа оплаты.
- Отслеживать статус заказа.
- Просматривать историю ранее оформленных заказов.
- Управлять личными данными и сохранёнными адресами.

Основной пользовательский сценарий выглядит следующим образом: пользователь выбирает ресторан, просматривает доступные товары, добавляет необходимые позиции в корзину, проверяет состав и итоговую стоимость, указывает адрес доставки и способ оплаты, после чего подтверждает заказ.

После оформления заказа информация передаётся ресторану и службе доставки. Пользователь получает возможность отслеживать изменение статуса заказа.

Проект реализуется как SPA (Single Page Application). Клиентская часть отвечает за отображение интерфейса и взаимодействие с пользователем, а серверная часть обрабатывает бизнес-логику, работу с данными и обмен информацией между отдельными компонентами системы.

## 2. Основания для разработки

[svg](https://github.com/Daniil-17102007/engineering#2-%D0%BE%D1%81%D0%BD%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F-%D0%B4%D0%BB%D1%8F-%D1%80%D0%B0%D0%B7%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%BA%D0%B8)

Разработка данного приложения инициирована на основе следующих факторов:

- **Анализ рынка:** высокий спрос на сервисы доставки готовой еды в городской среде.
- **Бизнес-задача:** создание удобного решения для объединения пользователей и ресторанов в единой системе.
- **Техническая необходимость:** необходимость автоматизировать процесс выбора товаров, формирования корзины и оформления заказа.
- **Внутренние потребности:** стандартизация процессов приёма заказов для ресторанов-партнёров и автоматизация работы службы доставки.

Разрабатываемая система должна упростить взаимодействие между всеми участниками процесса и сократить количество ручных операций.

## 3. Назначение продукта

[svg](https://github.com/Daniil-17102007/engineering#3-%D0%BD%D0%B0%D0%B7%D0%BD%D0%B0%D1%87%D0%B5%D0%BD%D0%B8%D0%B5-%D0%BF%D1%80%D0%BE%D0%B4%D1%83%D0%BA%D1%82%D0%B0)

### Целевая аудитория

[svg](https://github.com/Daniil-17102007/engineering#%D1%86%D0%B5%D0%BB%D0%B5%D0%B2%D0%B0%D1%8F-%D0%B0%D1%83%D0%B4%D0%B8%D1%82%D0%BE%D1%80%D0%B8%D1%8F)

1. **Конечные пользователи:** физические лица, желающие заказать еду с доставкой на дом или в офис.
2. **Рестораны и кафе:** заведения общественного питания, подключающиеся к платформе для приёма заказов.
3. **Администраторы платформы:** пользователи, управляющие ресторанами, товарами, акциями и заказами.
4. **Курьеры:** исполнители доставки, получающие информацию о назначенных заказах.

### Основные бизнес-цели

[svg](https://github.com/Daniil-17102007/engineering#%D0%BE%D1%81%D0%BD%D0%BE%D0%B2%D0%BD%D1%8B%D0%B5-%D0%B1%D0%B8%D0%B7%D0%BD%D0%B5%D1%81-%D1%86%D0%B5%D0%BB%D0%B8)

- **Увеличение продаж:** обеспечение ресторанов дополнительным каналом сбыта.
- **Удобство пользователей:** понятный интерфейс с минимальным количеством шагов для оформления заказа.
- **Автоматизация:** автоматизация процессов от выбора товара до передачи заказа ресторану и курьеру.
- **Аналитика:** сбор информации о заказах и предпочтениях пользователей для дальнейшего улучшения сервиса.

## 4. Требования к ПО

[svg](https://github.com/Daniil-17102007/engineering#4-%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F-%D0%BA-%D0%BF%D0%BE)

Данный раздел описывает функциональные, нефункциональные и технологические требования, предъявляемые к разрабатываемой системе.

### 4.1. Функциональные требования

[svg](https://github.com/Daniil-17102007/engineering#41-%D1%84%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5-%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F)

- **Модуль аутентификации:**
  - Регистрация пользователя по email и паролю.
  - Вход и выход из учётной записи.
  - Восстановление доступа к аккаунту.
  - Разделение прав доступа для клиента, ресторана, курьера и администратора.

- **Каталог ресторанов:**
  - Просмотр списка доступных ресторанов.
  - Просмотр информации о ресторане, его рейтинге, кухне и ориентировочном времени доставки.
  - Поиск по названию ресторана и товара.
  - Фильтрация по цене, рейтингу, типу кухни и времени доставки.

- **Товар:**
  - Каждый товар содержит название, описание, стоимость, категорию, изображение и признак доступности для заказа.
  - Пользователь может открыть карточку товара и ознакомиться с его характеристиками.
  - Пользователь может выбрать количество товара и добавить его в корзину.
  - Для товара могут быть предусмотрены дополнительные параметры или добавки, если их предоставляет ресторан.

- **Корзина:**
  - Добавление товаров.
  - Удаление товаров.
  - Изменение количества каждой позиции.
  - Автоматический пересчёт стоимости при изменении состава корзины.
  - Отображение стоимости отдельных товаров.
  - Отображение стоимости доставки.
  - Отображение итоговой суммы.
  - Проверка наличия товаров перед оформлением заказа.

- **Заказ:**
  - Формирование заказа на основе содержимого корзины.
  - Фиксация состава заказа, количества товаров и стоимости на момент оформления.
  - Указание адреса доставки и контактных данных пользователя.
  - Выбор ближайшего или отложенного времени доставки.
  - Выбор способа оплаты.
  - После оформления заказу присваивается уникальный номер.
  - Заказ проходит последовательность статусов:
    - «создан»;
    - «принят рестораном»;
    - «готовится»;
    - «передан курьеру»;
    - «доставляется»;
    - «доставлен»;
    - «отменён».
  - Пользователь может просматривать состав заказа, его стоимость и текущий статус.
  - При необходимости заказ может быть отменён в соответствии с установленными правилами.

- **Оплата:**
  - Выбор доступного способа оплаты при оформлении заказа.
  - Передача платёжных данных во внешний платёжный сервис.
  - Получение результата операции оплаты.
  - Отображение пользователю информации об успешной или неуспешной оплате.

- **Доставка:**
  - Передача курьеру информации о назначенном заказе.
  - Отображение адреса доставки и необходимой информации о заказе.
  - Изменение статуса доставки.
  - Отображение пользователю актуального состояния заказа.

- **Личный кабинет:**
  - Просмотр и редактирование основных данных пользователя.
  - Просмотр истории заказов.
  - Повтор ранее оформленного заказа.
  - Управление сохранёнными адресами.

- **Административная панель:**
  - Добавление, изменение и удаление ресторанов и товаров.
  - Управление категориями и информацией о меню.
  - Управление промокодами и акциями.
  - Просмотр и контроль текущих заказов.
  - Управление учётными записями пользователей и ролями.

### 4.2. Нефункциональные требования

[svg](https://github.com/Daniil-17102007/engineering#42-%D0%BD%D0%B5%D1%84%D1%83%D0%BD%D0%BA%D1%86%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D1%8B%D0%B5-%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F)

- **Производительность:** API должно отвечать на 95% запросов за время < 300 мс при нагрузке до 5000 RPS.
- **Доступность:** время безотказной работы системы (SLA) — 99.9%.
- **Безопасность:**
  - Хранение паролей с использованием алгоритма bcrypt.
  - Использование HTTPS с валидными SSL-сертификатами.
  - Защита от основных угроз OWASP Top 10, включая SQL-инъекции, XSS и CSRF.
- **Масштабируемость:** возможность увеличения количества пользователей и нагрузки за счёт расширения серверных ресурсов.
- **Кроссплатформенность:** поддержка последних версий Google Chrome, Mozilla Firefox и Safari, а также адаптивный дизайн для мобильных устройств.

### 4.3. Технический стек (Требования к технологиям)

[svg](https://github.com/Daniil-17102007/engineering#43-%D1%82%D0%B5%D1%85%D0%BD%D0%B8%D1%87%D0%B5%D1%81%D0%BA%D0%B8%D0%B9-%D1%81%D1%82%D0%B5%D0%BA-%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F-%D0%BA-%D1%82%D0%B5%D1%85%D0%BD%D0%BE%D0%BB%D0%BE%D0%B3%D0%B8%D1%8F%D0%BC)

#### Frontend

[svg](https://github.com/Daniil-17102007/engineering#frontend)

- **Язык:** TypeScript / JavaScript.
- **Фреймворк:** React.
- **Сборщик:** Vite.
- **Интерфейс:** HTML5 и CSS3 с адаптивной вёрсткой.
- **Взаимодействие:** REST API по протоколу HTTPS.

Frontend отвечает за отображение каталога ресторанов, товаров, корзины, формы оформления заказа, личного кабинета и административного интерфейса.

#### Backend

[svg](https://github.com/Daniil-17102007/engineering#backend)

- **Язык:** Python 3.10+.
- **Фреймворк:** FastAPI / Django REST Framework.
- **База данных:** PostgreSQL.
- **Кэширование:** Redis.
- **Очереди задач:** Celery / RabbitMQ для асинхронных операций.
- **Сервер:** Gunicorn + Nginx.

Backend реализует бизнес-логику приложения: работу пользователей, ресторанов, товаров, корзин и заказов, обработку оплаты, изменение статусов и взаимодействие с базой данных.

#### Взаимодействие компонентов

[svg](https://github.com/Daniil-17102007/engineering#взаимодействие-компонентов)

Клиентская часть обращается к Backend через REST API.

Backend принимает запрос, проверяет права доступа и корректность данных, выполняет необходимую операцию и возвращает результат клиенту.

Данные о пользователях, товарах и заказах хранятся в PostgreSQL, а Redis используется для временных данных и ускорения отдельных операций.

Пример взаимодействия:

```text
Пользователь
     ↓
Frontend
     ↓
REST API
     ↓
Backend
     ↓
PostgreSQL
     ↓
Backend
     ↓
Frontend
     ↓
Пользователь

## 1. Введение

[svg](https://github.com/Daniil-17102007/engineering#1-введение)

Разрабатываемое приложение предназначено для онлайн-заказа еды из ресторанов и кафе. Пользователь может просматривать доступные блюда, добавлять товары в корзину, оформлять заказ, выбирать способ оплаты и отслеживать состояние доставки.

Приложение должно объединять основные этапы оформления заказа в одной системе: выбор ресторана, выбор товара, формирование корзины, оформление заказа, оплата и доставка.

Основной сценарий работы пользователя выглядит следующим образом:

1. Пользователь открывает приложение.
2. Авторизуется или регистрируется.
3. Выбирает ресторан.
4. Просматривает доступные товары.
5. Добавляет необходимые товары в корзину.
6. Проверяет состав и стоимость корзины.
7. Указывает адрес и способ доставки.
8. Выбирает способ оплаты.
9. Подтверждает заказ.
10. Получает информацию о статусе заказа.
11. Отслеживает процесс приготовления и доставки.

Система состоит из клиентской и серверной частей. Клиентская часть отвечает за отображение информации и взаимодействие с пользователем, а серверная часть — за обработку данных, работу с заказами, товарами, пользователями и базой данных.

## 2. Основания для разработки

[svg](https://github.com/Daniil-17102007/engineering#2-основания-для-разработки)

Необходимость разработки приложения связана с популярностью онлайн-заказа еды и необходимостью автоматизации процесса взаимодействия между пользователем, рестораном и службой доставки.

Приложение должно позволять пользователю быстро выбрать необходимые товары и оформить заказ без необходимости посещать ресторан лично или совершать телефонный звонок.

Основными причинами разработки являются:

- автоматизация процесса оформления заказов;
- сокращение времени на обработку заказов;
- удобный просмотр меню ресторанов;
- возможность управления корзиной;
- получение информации о стоимости заказа;
- отслеживание статуса заказа;
- хранение информации о пользователях и заказах;
- возможность дальнейшего расширения системы.

Приложение также должно обеспечивать возможность подключения новых ресторанов, добавления новых товаров и расширения функциональности.

## 4. Требования к системе

[svg](https://github.com/Daniil-17102007/engineering#4-требования-к-системе)

### 4.1. Функциональные требования

[svg](https://github.com/Daniil-17102007/engineering#41-функциональные-требования)

#### 4.1.1. Регистрация и авторизация

Пользователь должен иметь возможность зарегистрироваться в системе и войти в существующую учётную запись.

При регистрации пользователь указывает необходимые данные, после чего система создаёт учётную запись.

При авторизации система проверяет введённые данные и предоставляет пользователю доступ к его личному кабинету.

#### 4.1.2. Просмотр ресторанов

Пользователь должен иметь возможность просматривать список доступных ресторанов.

Для каждого ресторана должна отображаться основная информация:

- название;
- описание;
- адрес;
- режим работы;
- доступное меню.

#### 4.1.3. Товар

Товар является отдельной позицией меню ресторана.

Для каждого товара должна храниться следующая информация:

- название;
- описание;
- цена;
- категория;
- изображение;
- доступность для заказа.

Пользователь должен иметь возможность открыть карточку товара и ознакомиться с его информацией.

Также пользователь должен иметь возможность выбрать количество товара и добавить его в корзину.

Если для товара предусмотрены дополнительные параметры, пользователь должен иметь возможность выбрать необходимые добавки или варианты.

#### 4.1.4. Корзина

Корзина содержит товары, которые пользователь собирается заказать.

Пользователь должен иметь возможность:

- добавить товар в корзину;
- удалить товар;
- изменить количество товара;
- просмотреть состав корзины;
- увидеть стоимость каждого товара;
- увидеть общую стоимость заказа.

При изменении количества товаров итоговая стоимость должна пересчитываться автоматически.

Перед оформлением заказа система должна проверить наличие выбранных товаров.

#### 4.1.5. Заказ

Заказ формируется на основании содержимого корзины после подтверждения пользователем.

При оформлении заказа должны фиксироваться:

- уникальный номер заказа;
- пользователь;
- выбранные товары;
- количество каждого товара;
- стоимость товаров;
- итоговая стоимость;
- адрес доставки;
- контактные данные;
- способ оплаты;
- выбранное время доставки;
- дата и время создания заказа.

После оформления заказа его состав и стоимость должны сохраняться. Изменение товара в меню не должно изменять уже оформленный заказ.

Заказ должен иметь определённый статус.

Основные статусы:

1. Создан.
2. Принят рестораном.
3. Готовится.
4. Передан курьеру.
5. Доставляется.
6. Доставлен.
7. Отменён.

Пользователь должен иметь возможность открыть заказ и посмотреть его состав, стоимость и текущий статус.

При необходимости заказ может быть отменён в соответствии с правилами системы.

#### 4.1.6. Оплата

Система должна предоставлять возможность выбора способа оплаты.

В зависимости от выбранного способа пользователь может оплатить заказ онлайн или выбрать другой доступный способ оплаты.

После оплаты система должна сохранить информацию о результате операции.

#### 4.1.7. Доставка

Пользователь должен иметь возможность указать адрес доставки.

Система должна хранить информацию об адресе и связывать её с соответствующим заказом.

Пользователь должен видеть информацию о текущем состоянии доставки.

#### 4.1.8. Личный кабинет

В личном кабинете пользователь может:

- просматривать свои данные;
- изменять контактную информацию;
- просматривать историю заказов;
- открывать информацию о ранее оформленных заказах;
- просматривать текущие заказы.

#### 4.1.9. Панель администратора

Администратор должен иметь отдельный интерфейс для управления системой.

В панели администратора необходимо предусмотреть:

- управление ресторанами;
- управление товарами;
- управление пользователями;
- просмотр заказов;
- изменение статусов заказов;
- изменение доступности товаров.

### 4.2. Нефункциональные требования

[svg](https://github.com/Daniil-17102007/engineering#42-нефункциональные-требования)

#### Производительность

Основные страницы приложения должны загружаться за приемлемое время.

Операции добавления товара в корзину, изменения количества и оформления заказа должны выполняться без заметных задержек.

#### Доступность

Приложение должно быть доступно пользователям в течение всего времени работы сервиса.

При возникновении ошибок система должна корректно сообщать о проблеме и не терять данные пользователя.

#### Надёжность

Информация о заказе не должна теряться после его оформления.

Система должна корректно обрабатывать ситуации, связанные с недоступностью товара или ошибками при оплате.

#### Безопасность

Доступ к персональным данным пользователя должен быть ограничен.

Пароли и другие важные данные не должны храниться в открытом виде.

Доступ к административным функциям должен предоставляться только пользователям с соответствующими правами.

#### Масштабируемость

Архитектура приложения должна позволять добавлять новые рестораны, товары и пользователей без необходимости полной переработки системы.

В дальнейшем должна быть предусмотрена возможность увеличения количества пользователей и заказов.

#### Совместимость

Приложение должно корректно работать в современных браузерах.

Интерфейс должен адаптироваться под разные размеры экранов, включая компьютеры, планшеты и мобильные устройства.

#### Удобство использования

Интерфейс должен быть понятным пользователю.

Основные действия, такие как выбор товара, добавление в корзину и оформление заказа, должны выполняться последовательно и без лишних действий.

### 4.3. Технический стек

[svg](https://github.com/Daniil-17102007/engineering#43-технический-стек)

### Frontend

[svg](https://github.com/Daniil-17102007/engineering#frontend)

Для разработки клиентской части приложения используются:

- **HTML5** — структура страниц;
- **CSS3** — оформление и адаптивность интерфейса;
- **JavaScript / TypeScript** — реализация логики приложения;
- **React** — создание пользовательского интерфейса;
- **Vite** — запуск и сборка frontend-приложения;
- **REST API** — взаимодействие с серверной частью;
- **HTTPS** — безопасная передача данных.

Frontend отвечает за отображение ресторанов, товаров, корзины, заказов и личного кабинета пользователя.

### Backend

[svg](https://github.com/Daniil-17102007/engineering#backend)

Для серверной части приложения используются:

- **Python 3.10+** — основной язык программирования;
- **FastAPI / Django REST Framework** — разработка серверной части и API;
- **PostgreSQL** — хранение данных;
- **Redis** — хранение временных данных и кэширование;
- **Celery / RabbitMQ** — выполнение фоновых задач;
- **Gunicorn** — запуск серверного приложения;
- **Nginx** — обработка внешних запросов.

Backend отвечает за обработку запросов, работу с пользователями, товарами, корзиной, заказами, оплатой и базой данных.

### Взаимодействие компонентов

Frontend отправляет запросы к Backend через API.

Backend обрабатывает запрос, выполняет необходимые операции и обращается к базе данных.

После обработки запроса Backend возвращает результат во Frontend, где информация отображается пользователю.

Пример взаимодействия:

```text
Пользователь
     ↓
Frontend
     ↓
REST API
     ↓
Backend
     ↓
PostgreSQL
     ↓
Backend
     ↓
Frontend
     ↓
Пользователь
